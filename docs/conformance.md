# Conformance and evidence

This document traces the mechanical contracts in [Open Inquiry executable specification 0.4](spec/open-inquiry-0.4.md) to the implementation boundaries intended to enforce them. It separates implemented mechanisms, mechanical observations, and questions that require live investigation. Passing a host test is not evidence that a model understood a criticism or that an explanation improved.

The specification is the supplied implementation source. Its semantic authority and subordinate profile are named in its authority register; those separately named documents were not supplied in this repository-building request. This implementation must not claim an independent audit against unavailable authority bytes.

The integration agreement is [IMPLEMENTATION_INTERFACES.md](../IMPLEMENTATION_INTERFACES.md). The reader-facing entry point is [the code map](code-map.md). The matrix identifies implemented responsibilities and the actual tests exercising them. Evidence remains scoped to those tests; the limitations below identify optional adapters and research claims that were not established.

## Evidence levels

| Evidence label | What the evidence establishes | What it does not establish |
| --- | --- | --- |
| Pending | The requirement and intended implementation boundary have been identified. | That implementation exists or passes a test. |
| Component observation | An identified module produced the expected result with recorded fixture inputs. | That the composed scheduler dispatches the right prompt or that a remote provider obeys its settings. |
| Dispatch observation | A test inspected the complete actual request at the provider boundary and the resulting host state. | That the participant noticed, understood, or used the material. |
| Persistence observation | A saved state was loaded and the specified operation was checked again. | Deterministic replay of an event prefix, unless the initial state, reducer, event sequence, and versions were also fixed. |
| Live observation | An identified real provider, parser, or execution interface was exercised with its actual configuration and measured outcomes. | General effectiveness, creativity, truth, or explanatory universality. |

A synthetic counter can establish packing arithmetic for that counter. It is not a provider tokenizer. A scripted participant can establish the host's handling of ordinary prose. It is not a live experiment on explanatory improvement. Test counts are work records and must never feed the production scheduler as merit scores.

| S14 | Part II: dependency effects apply to explicit essential uses only. | `engine.py` dependency declarations and pending queue | Withdrawing one premise suppresses dependent application supply with a notice while an independent application and background citation remain unaffected. The conclusive result needed by S10 concerns the registered predicate. For literal existence, a match can be conclusive even when full-source scan coverage is false. Treating every incomplete scan as an unresolved already-found existence query would conflate the two facts in S05. Conversely, an unfinished unsuccessful search must never report absence.
