# Conformance and evidence

This document traces the mechanical contracts in [Open Inquiry executable specification 0.4](spec/open-inquiry-0.4.md) to the implementation boundaries intended to enforce them. It separates implemented mechanisms, mechanical observations, and questions that require live investigation. Passing a host test is not evidence that a model understood a criticism or that an explanation improved.

The specification is the supplied implementation source. Its semantic authority and subordinate profile are named in its authority register; those separately named documents were not supplied in this repository-building request. This implementation must not claim an independent audit against unavailable authority bytes.

During construction, the integration agreement is [IMPLEMENTATION_INTERFACES.md](../IMPLEMENTATION_INTERFACES.md). The reader-facing entry point is [the code map](code-map.md). A named module below identifies an intended responsibility, not proof that its behavior has been delivered. “Pending” means that no independently inspected implementation result is recorded in this matrix. It does not mean that the corresponding requirement is optional.

## Evidence levels

| Evidence label | What the evidence establishes | What it does not establish |
| --- | --- | --- |
| Pending | The requirement and intended implementation boundary have been identified. | That implementation exists or passes a test. |
| Component observation | An identified module produced the expected result with recorded fixture inputs. | That the composed scheduler dispatches the right prompt or that a remote provider obeys its settings. |
| Dispatch observation | A test inspected the complete actual request at the provider boundary and the resulting host state. | That the participant noticed, understood, or used the material. |
| Persistence observation | A saved state was loaded and the specified operation was checked again. | Deterministic replay of an event prefix, unless the initial state, reducer, event sequence, and versions were also fixed. |
| Live observation | An identified real provider, parser, or execution interface was exercised with its actual configuration and measured outcomes. | General effectiveness, creativity, truth, or explanatory universality. |

A synthetic counter can establish packing arithmetic for that counter. It is not a provider tokenizer. A scripted participant can establish the host's handling of ordinary prose. It is not a live experiment on explanatory improvement. Test counts are work records and must never feed the production scheduler as merit scores.

The conclusive result needed by S10 concerns the registered predicate. For literal existence, a match can be conclusive even when full-source scan coverage is false. Treating every incomplete scan as an unresolved already-found existence query would conflate the two facts in S05. Conversely, an unfinished unsuccessful search must never report absence.

## Observed component audit

On 7 September 2026, an independent local run executed 87 tests across `test_collection.py`, `test_checking.py`, `test_context.py`, `test_resources.py`, and `test_providers.py`; all passed. The audit inspected the corresponding source boundaries and prompted repairs to bounded source-selection input, atomic link admission, bounded use-notice lookup, and incomplete provider accounting before this run. Provider transport tests use fixtures or mocked responses. This is component evidence; it does not establish the composed engine transitions still marked pending or any live model result.

## Release reporting

Before presenting a requirement as covered, replace its pending evidence with an actual test location and observed result. For requirements whose effect is on a later model request, a component fixture alone is insufficient: inspect the complete actual dispatch after the transition. For persistence claims, repeat the relevant operation after loading saved state. For provider claims, name the adapter, accounting mode, and limitations actually exercised.

An unsupported optional adapter may be explicitly absent. Its absence must not disable the prose-only core. A mandatory host contract cannot be waived by renaming an implementation a compact profile: configurable numerical recipes remain distinct from semantic obligations and permission guards.

Live comparisons require separate evidence. Begin learning-off, observe, and learning-on conditions from the same initial installed method, source collection, provider configuration, and resource envelope. Include control overhead, displaced calls, missing observations, and contrary or inconclusive results. No mechanical test suite, live assessor vote, or count of successful trials certifies creativity or gives an explanation immunity from criticism.
